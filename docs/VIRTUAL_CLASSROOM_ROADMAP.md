# Дорожная карта внедрения виртуального класса Edusfera (Roadmap & TODO)

Этот документ описывает инженерные этапы перехода виртуального класса Edusfera от текущей архитектуры к масштабируемой микросервисной модели с единым API-шлюзом, оптимизированной видеосвязью, интерактивной канбан-доской, вездесущим ИИ-ассистентом и SaaS-квотированием.

---

## 🧭 Текущее состояние vs Целевая архитектура

### Что есть сейчас:
1. **Laravel-монолит** — управляет сессиями классов, генерирует JWT-токены доступа, хранит заметки и файлы локально.
2. **Go-микросервис `edusfera-ledger`** — отвечает за кошельки и транзакции (биллинг).
3. **Go-микросервис `edusfera-media`** — реализует базовый WebRTC SFU на базе библиотеки Pion и простую синхронизацию рисования на Canvas (доска).

### Целевое видение:
* Клиент взаимодействует со всеми сервисами через **Единый API Gateway**.
* Видеосвязь гарантированно работает на каналах от **1-2 Мбит/с** в SD-качестве с автоматическим приоритетом аудио.
* Вместо простой доски рисования — интерактивный **Workspace (Канбан-доска)** реального времени с блочной структурой и ИИ-управлением.
* **Вездесущий ИИ-ассистент** знает контекст текущего экрана, помогает прямо в классе и автоматически генерирует саммари урока и ДЗ на основе транскрипта.
* Действует жесткое **квотирование S3-хранилища (2 ГБ на базовом тарифе)** и лимиты ИИ-токенов с мягкими триггерами к оплате тарифа Pro.

---

## ⚖️ Архитектурный выбор WebRTC: Evolve Pion vs LiveKit/Jitsi

Перед стартом работ необходимо утвердить стратегию развития видеоядра:

| Критерий | Развитие текущего Go/Pion SFU (`edusfera-media`) | Интеграция готового Open-Source (LiveKit) |
| :--- | :--- | :--- |
| **Сложность внедрения** | 🔴 **Очень высокая**. Придется вручную писать логику распределения потоков, BWE (Bandwidth Estimation), джиттер-буфер и обработку RTCP. | 🟢 **Низкая**. Готовый сервер, стабильные SDK для бэкенда (Go/PHP) и фронтенда (JS/Alpine.js). |
| **Оптимизация под слабый интернет** | 🟡 **Сложная ручная настройка**. Требуется самостоятельно реализовать Simulcast и динамическое переключение битрейтов. | 🟢 **Из коробки**. LiveKit автоматически режет качество видео при проседании канала, сохраняя стабильный звук. |
| **Масштабирование и кластеризация** | 🔴 **Сложно**. Нужна ручная разработка балансировщика комнат между несколькими инстансами SFU. | 🟢 **Из коробки**. Поддержка Redis-based кластеризации и горизонтального масштабирования. |
| **Кастомизация Data Channels** | 🟢 **Полная свобода**. Удобно для низкоуровневой интеграции с интерактивной доской. | 🟢 **Высокая**. Доступны надежные и быстрые Data Channels для передачи кастомного JSON. |

> [!TIP]
> **Рекомендация для MVP:** Рекомендуется развернуть **LiveKit Server** на собственных мощностях. Это сэкономит от 3 до 6 месяцев сложной низкоуровневой сетевой разработки WebRTC и позволит сфокусироваться на создании уникальных бизнес-фич (Канбан-доска, ИИ-ассистент).
> 
> Если же требуется максимальный контроль над памятью и трафиком без оверхеда сторонних платформ, мы можем продолжить развивать `edusfera-media` на Pion Go.

## 📋 Подробный TODO-лист внедрения

### 1. Ядро интеграции: Универсальный API-шлюз (API Gateway)
*Маршрутизация всех запросов через единый входной порт и унификация авторизации.*

- [ ] **Выбор и развертывание Gateway:**
  - [ ] Настроить **Kong** или **APISIX** (предпочтительно для декларативного YAML-конфигурирования) в Docker-окружении.
  - [ ] Сконфигурировать CORS-политики на уровне шлюза.
- [ ] **Настройка правил маршрутизации (Routing Rules):**
  - [ ] `/api/v1/ledger/*` ➡️ `edusfera-ledger` (порт :8080)
  - [ ] `/ws/*` или `/rtc/*` ➡️ `edusfera-media` (или LiveKit)
  - [ ] `/api/v1/ai/*` ➡️ будущий микросервис ИИ
  - [ ] `/*` (все остальные запросы, Filament, Web-страницы) ➡️ Laravel-монолит
- [ ] **Единая аутентификация (Global JWT):**
  - [ ] Перенести валидацию JWT-токенов с плеч микросервисов на API Gateway.
  - [ ] Реализовать прокидывание метаданных пользователя во внутреннюю сеть через HTTP-заголовки (например, `X-User-Id`, `X-User-Role`, `X-User-Email`).
  - [ ] Обновить `JWTMiddleware` в `edusfera-ledger` и систему авторизации в `edusfera-media` для чтения этих заголовков вместо прямой расшифровки JWT.

### 2. Стриминговый микросервис (Оптимизация видеосвязи)
*Обеспечение стабильного соединения при пропускной способности 1-2 Мбит/с.*

- [ ] **Адаптивный битрейт (Simulcast):**
  - [ ] Настроить кодирование видео на клиенте в трех разрешениях (Low - 180p, Medium - 360p, High - 720p).
  - [ ] Внедрить на сервере алгоритмы оценки пропускной способности (BWE / GCC) для своевременного переключения потоков.
- [ ] **Агрессивная оптимизация при плохом канале:**
  - [ ] Реализовать автоматическое отключение входящего видео (Video Mute) у участников, чья скорость падает ниже 300 Кбит/с, сохраняя только аудиопоток.
  - [ ] Установить приоритет трафика: `Аудио (Opus) -> Сигнальные сообщения Websocket -> Видео (VP8/H.264)`.
- [ ] **Инфраструктура обхода NAT (STUN/TURN):**
  - [ ] Развернуть собственный сервер **Coturn** с поддержкой TURN over TLS (порт 443) для пробива жестких корпоративных файрволов.
  - [ ] Прописать параметры TURN в `config/classroom.php` Laravel-приложения.

### 3. Интерактивное рабочее пространство Workspace (Канбан-доска)
*Переход от простого рисования к многофункциональной доске с состоянием (Stateful Workspace).*

- [ ] **Архитектура состояния (Workspace State DB & Memory):**
  - [ ] Спроектировать JSON-схему доски:
    ```json
    {
      "workspace_id": "uuid",
      "columns": [
        { "id": "col-1", "title": "План урока", "cards": [...] }
      ],
      "canvas_layers": [...]
    }
    ```
  - [ ] Интегрировать хранение промежуточного состояния доски в Redis (для быстрого чтения/записи) с периодическим сбросом в PostgreSQL (через Laravel API).
- [ ] **WebSocket-синхронизация реального времени:**
  - [ ] Создать отдельный микросервис Workspace на Go (или расширить `edusfera-media` новой WebSocket-точкой `/ws/workspace`).
  - [ ] Реализовать протокол синхронизации изменений на базе CRDT (например, библиотека Yjs) для исключения конфликтов одновременного редактирования учителем и учеником.
- [ ] **Разработка UI-компонентов доски (Alpine.js + HTML5 Drag & Drop):**
  - [ ] Создать интерфейс перетаскивания карточек (Kanban-сетка).
  - [ ] Интегрировать встроенные примитивы:
    - [ ] **Заметка:** блок форматированного текста (Markdown-редактор).
    - [ ] **Чек-лист:** список подзадач с отметками о выполнении.
    - [ ] **Код-фрейм:** мини-редактор с подсветкой синтаксиса (CodeMirror) для уроков IT.
    - [ ] **Медиа-блок:** рендер загруженных картинок или страниц PDF.
    - [ ] **Таймер:** запускаемый учителем обратный отсчет времени на выполнение задания.
- [ ] **Слой рисования (Canvas Overlay):**
  - [ ] Оставить возможность свободного рисования поверх доски или внутри конкретных карточек с трансляцией координат через Websocket.

### 4. Вездесущий ИИ-ассистент (Omnipresent AI)
*Контекстный ИИ, доступный в любой точке платформы и автоматизирующий рутину.*

- [ ] **Глобальный AI-виджет на фронтенде:**
  - [ ] Разработать сворачиваемую панель ИИ-чата (AI Drawer), доступную во всех разделах личного кабинета и виртуального класса.
- [ ] **Контекстная осведомленность (Context Broker):**
  - [ ] Написать JS-колбеки для автоматического сбора контекста:
    - На странице расписания ➡️ список ближайших уроков.
    - В виртуальном классе ➡️ текущая активная карточка на канбан-доске.
    - В чате ➡️ последние 10 сообщений.
  - [ ] Реализовать сборку системного промпта на бэкенде с учетом собранных метаданных.
- [ ] **ИИ-Агент канбан-доски (Local Agent):**
  - [ ] Написать системный промпт для LLM, переводящий свободный текст пользователя ("Добавь колонку 'Физика' с двумя карточками: 'Формула F=ma' и 'Закон Ньютона'") в валидный JSON изменений доски.
  - [ ] Создать API-ручку на бэкенде доски, которая принимает этот JSON от LLM, валидирует его безопасность и применяет к текущей Websocket-сессии.
- [ ] **Саммаризация уроков и автогенерация ДЗ:**
  - [ ] Настроить запись аудиопотока в микросервисе видеосвязи.
  - [ ] Подключить фоновый воркер для транскрибации записи через **Whisper** (или API OpenAI/локальный сервис).
  - [ ] Написать LLM-пайплайн, анализирующий транскрипт урока и автоматически генерирующий:
    - Краткое саммари для родителя (в модель `tutor_report_summary`).
    - Карточку с домашним заданием на канбан-доске (в модель `homework_assignments`).

### 5. Инфраструктура хранения и биллинг (SaaS-квоты)

- [ ] **Переход на S3-хранилище:**
  - [ ] Развернуть **MinIO** для локальной разработки и настроить S3-совместимое облако (AWS, Yandex Cloud) для продакшена.
  - [ ] Обновить драйвер файлового хранилища в Laravel-монолите на `s3`.
  - [ ] Реализовать изоляцию файлов в бакете по структуре: `bucket/users/{user_id}/classroom/{session_id}/file_name`.
- [ ] **Микросервис квотирования (Storage & AI Quotas):**
  - [ ] Создать механизм подсчета суммарного объема файлов пользователя в БД.
  - [ ] Внедрить Middleware проверки доступного места при каждом запросе на `POST /classroom/upload-file`.
  - [ ] Добавить в бэкенд ИИ-ассистента счетчик израсходованных токенов / запросов за текущий расчетный период.
- [ ] **Мягкие и жесткие триггеры лимитов:**
  - [ ] При превышении 90% лимита (1.8 ГБ из 2 ГБ) отправлять WebSocket-событие для показа предупреждения: *"Ваше облако заполнено на 90%. Обновите тариф до Pro"*.
  - [ ] При превышении 100% блокировать загрузку новых файлов и вызовы ИИ-ассистента, перенаправляя пользователя на страницу оплаты (Checkout).

## 📈 Метрики успешного внедрения

Для контроля качества реализации на каждом этапе необходимо отслеживать следующие показатели:
* **Качество связи:** Доля звонков с потерей пакетов аудио < 1% (цель: > 98% сессий).
* **Скорость синхронизации доски:** Задержка отображения действий (Draw/Move) между участниками < 150 мс.
* **Точность ИИ-ассистента:** Процент успешного парсинга ИИ-команд для доски в валидный JSON (цель: > 90%).
* **Конверсия:** Рост переходов пользователей на тариф **Pro** при срабатывании алертов о заполнении лимита 2 ГБ.
